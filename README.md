# CS-320-SNHU

I ensure my software is functional and secure by following secure coding practices, conducting thorough testing, and regularly assessing vulnerabilities. Functional testing allows me to verify that the software meets its requirements and behaves as expected. Security testing, including vulnerability scanning and dependency analysis, helps identify weaknesses that could be exploited by attackers. I used tools such as OWASP Dependency-Check and JUnit to verify functionality and identify potential security risks. By combining testing, code reviews, and security assessments, I can develop software that is both reliable and secure.

I interpret user needs by carefully analyzing project requirements, identifying expected functionality, and understanding the problems users are trying to solve. I translate those requirements into software features and design decisions that support the user's goals. Throughout development, I use testing and feedback to confirm that the application meets those needs. For example, in the Artemis Financial project, I recognized the need to protect sensitive financial information and incorporated security measures such as HTTPS communication and cryptographic hashing to address the client's requirements. Understanding user needs helps ensure that the final product is both useful and effective.

I approach software design by first gathering and analyzing requirements, then breaking the project into smaller, manageable components. I identify how different parts of the system will interact and create a structure that promotes maintainability, security, and scalability. Object-oriented design principles help me organize code into logical classes and methods, making the software easier to test and update. I also consider potential risks and security concerns early in the design process. By planning before implementation and using an organized development approach, I can create efficient, reliable software solutions aligned with user requirements.
